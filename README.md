# 流云织小说工作台

> 以 Obsidian 库为底层知识底座的小说创作工作台。
> 它不是笔记软件，也不是小说排版工具。**它是一台「记住」整本书的机器。**

一句话：把小说的全部构成（大纲、章纲、章节、线索、人物、设定、体系、境界、世界）存成可互相串联、可反向回溯的 Markdown 笔记，并让 AI 能直接读写这套知识库。

---

## 它解决什么

写长篇小说，难点不在「写」，在**记住**：

- 这个人物三卷前说过什么？
- 那条伏笔埋在第七章还是第十七章，收了没有？
- 两个角色到底结没结仇？
- 这个世界的灵气在东域和西荒是不是同一种东西？
- 主角现在同时修几套体系，各自到第几阶？

人脑记不住，就会写出矛盾，最后烂尾。

---

## 两个核心机制

### 作用域 scope —— 承载宏大世界观

每个条目可声明「我在哪生效」：

```yaml
条目：行星级
  type: 境界
  scope:
    space: 宇宙
    time:  宇宙历

条目：武者
  type: 境界
  scope:
    space: 地球
    time:  21世纪
```

系统据此算出「此刻生效的规则集合」。地球章节生效武者，宇宙章节生效宇宙修炼，**同一本书内规则隔离**。

这同时落实了三件事：

- **并行** = 同一作用域内多套体系共存（武者 ‖ 精神念师）
- **串行** = 作用域更替，旧体系被覆盖（地球 → 宇宙）
- **互相影响** = 靠关系表达（机械族 —对立→ 修炼）

### 概念别名 _concept —— 同物异名

一块地方叫灵气，另一块叫源力，天外叫星尘 —— 同一个东西，三种叫法，性质可能完全不同。

```yaml
type: _concept
name: 天地本源之力
aliases:
  - name: 灵气
    region: 东域
    nature: 温和，可吸纳
  - name: 源力
    region: 西荒
    nature: 暴烈，需炼化
    conflict: true
```

`[[灵气]]` `[[源力]]` `[[星尘]]` 全部指向同一概念；`conflict: true` 让系统能提示「灵气体系修士进入西荒将受压制」。

## 根本原则

### 没有题材

**内核里没有「题材」「分类」「体裁」字段。一个字都没有。**

「玄幻 / 修仙 / 都市 / 科幻」是书架标签，不是文本结构。用货架编号描述一本书的结构，必然被创新打死。

### 真相唯一

```
.md 文件 = 唯一真相
索引     = 可重建的派生数据（删掉不丢任何内容）
```

用 Obsidian 打开同一个文件夹，能看到完整内容与原生关系图。**没有第二份数据，没有导出步骤，没有同步动作。**

### 先写后归类

正文里写 `罗峰踏入[[虚拟宇宙]]`，系统立刻接受：虚拟宇宙成为一个条目，可以暂时没有类型、没有属性，不报错、不弹窗。

归类是**后置的、可选的、随时可改的**。归入「未归类」，永不阻塞创作。

### 七种视图，新类型不产生新界面

`list` / `ladder` / `tree` / `graph` / `timeline` / `swimlane` / `table`

列表、阶梯、树、时间轴、表格、泳道按类型自动切换；关系图在「关系网」页展示。作者新建「符箓」类型 = 写一篇笔记，**不改代码**。

## 快速开始

需要 Node ≥ 22.13（用到原生 TypeScript 与 `node:sqlite`）。

```bash
# 安装
pnpm install

# 造一本演示小说（28 篇笔记，含人物/境界/伏笔/章节）
pnpm seed

# 构建前端
pnpm build:web

# 启动
pnpm start
# → http://127.0.0.1:5178
```

工作区默认在 `.workspace/`，可用环境变量或参数指定：

```bash
LOOM_WORKSPACE=F:/novels LOOM_PORT=5178 pnpm start
# 或
node apps/server/src/main.ts --root F:/novels --port 5178
```

开发模式（前端热更新）：

```bash
pnpm dev:server   # 终端 1
pnpm dev:web      # 终端 2 → http://127.0.0.1:5173
```

## 三大库 · 三级目录

```
一级（固定 3 项）
  └─ 二级（该库下的条目，数量不限，超出滚动）
      └─ 三级（该条目的子项，每组 ≤ 5）
```

**再往下（四级及以后）不进导航栏，放右侧主画面。** 导航栏是骨架，主画面是血肉。

| 库 | 做什么 | 不做什么 |
|---|---|---|
| **小说库** | 名录、摘要、编辑元信息、删除、切换（像看公司员工名录） | 不展开书的完整内容 |
| **项目库** | 单本小说的全部内容，按创作顺序：大纲 → 章纲 → 线索 → 人物 → 设定 → 关系网 | 不管其他书 |
| **工具库** | 知识串联、AI 接口、检查、统计（**同一平面，不分层**，知识链接排第一） | 不存内容，只做加工 |

### 导航细则

- 三个一级目录**都可收缩**，右侧向下箭头
- 小说库 / 项目库右侧另有**墨绿加号**（新建小说 / 添加项目）；工具库没有
- **二级一律不加粗**，靠缩进区分层级；一级加粗、品牌「流云织」墨绿
- 一级之间 1px 分割线，界限清晰
- **全局搜索**在品牌区右侧（放大镜图标）
- **设置 / 导入导出**在右下角常驻工具条
- **MCP 对内对外在同一页**，用分段切换
- 工具库每个二级就是一个功能页，**没有三级**

### 设置 10 项（原工具库并入设置）

普通编辑 · 信息关系网 · MCP · 一致性检查 · 统计 · 类型管理 · 模板管理 · 插件 · Skills · 回收站

## MCP：双向通道

这是**开源项目给其他 agent 接入的**，不只自用。

### 对外（本工作台是 Server）

```json
{
  "mcpServers": {
    "liuyun-loom": {
      "command": "node",
      "args": ["<项目路径>/apps/server/src/mcp-stdio.ts"],
      "env": { "LOOM_WORKSPACE": "<工作区路径>" }
    }
  }
}
```

远程 agent 用 `POST /mcp`（streamable-http）。

**18 个工具，只读 12 + 写入 6：**

| 只读 | 用途 |
|---|---|
| `loom_world_overview` | 世界总览（规模、健康、类型分布） |
| `loom_list_projects` | 所有小说列表 |
| `loom_search` | 全文检索 |
| `loom_read_note` | 读一篇笔记全文 + 出链 + 反链 |
| `loom_list_entries` | 条目清单 |
| `loom_world_map` | 关系图 |
| `loom_types` | 类型定义 |
| `loom_concepts` | 概念别名 |
| `loom_active_at` | **给定坐标，算出生效规则** |
| `loom_check` | 一致性检查 |
| `loom_backlinks` | 反向链接 |
| `loom_trace` | 全链路回溯 |

| 写入 | 用途 |
|---|---|
| `loom_create_entry` | 新建条目（类型可空） |
| `loom_update_entry` | 更新条目 |
| `loom_create_type` | 定义新类型 |
| `loom_link` | 建立关系 |
| `loom_write_chapter` | 写章节 |
| `loom_create_project` | 新建小说 |

工具描述**面向叙事动作，不面向数据库表**：接进来的 agent 才知道什么时候该用哪个。

### 对内（本工作台是 Client）

接入外部 MCP 服务（搜索、翻译、生成……），支持 stdio 与 http，带连接测试与工具级权限控制。

## 目录结构

```
.
├── packages/core/          内核（零依赖）
│   ├── src/types.ts        数据模型（唯一真相的类型定义）
│   ├── src/yaml.ts         YAML 子集解析/序列化
│   ├── src/markdown.ts     Obsidian 风格 Markdown → 结构化 blocks
│   ├── src/note.ts         笔记解析、作用域、别名、类型、等级
│   ├── src/vault.ts        文件系统、链接解析、原子写入、路径安全
│   ├── src/relations.ts    关系推导、概念索引、视图推断
│   ├── src/index-db.ts     SQLite 索引 + FTS5 trigram 中文检索
│   ├── src/engine.ts       单本书的全部内存状态
│   ├── src/workspace.ts    多本书管理、素材包
│   ├── src/packs.ts        8 个素材包
│   └── test/               126 项测试
├── apps/server/            服务（零框架，仅 Node 内置）
│   ├── src/http.ts         路由、响应、SSE、静态资源
│   ├── src/routes.ts       全 API
│   ├── src/mcp.ts          MCP Server + Client
│   ├── src/mcp-stdio.ts    stdio 入口
│   └── src/main.ts         HTTP 入口
├── apps/web/               前端（React + Vite，零 UI 框架）
│   ├── src/styles/         流云白 / 清潭蓝 / 五种细纹 / 三层渐变
│   ├── src/Nav.tsx         三级导航
│   ├── src/Graph.tsx       力导向关系图（d3-force，按度数定大小）
│   ├── src/Markdown.tsx    blocks → React 组件（防 XSS）
│   └── src/pages/          各页面
├── scripts/                冒烟测试与演示数据
```

## 这一轮不做什么

| 不做 | 原因 |
|---|---|
| AI 自动生成章节 | 本轮只做工作台与知识底座 |
| 多人协作 | 本地单机 |
| 云同步 | 靠 Git / 用户网盘 |
| 移动端 | 桌面优先 |
| EPUB / PDF 导出 | 后续 |
| 版本历史 | 靠 Git |
